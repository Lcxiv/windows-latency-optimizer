Where it started

One freeze exposed
the whole gap.

"Computer froze on last boot." Decoded the dump: nvlddmkm DPC watchdog. Confirmed, fixed, verified P0 held. But the entire RCA — the most valuable hour the product ever produced — ran outside the app. Hand PowerShell + WinDbg. No dashboard, no audit, no diagnose.

The value lives in incident-response. The app was built for monitoring. Mismatch.

The pivot
Not a dashboard with an LLM bolted on.
A forensics collector + a reasoning layer + a verdict.

The 145 scripts are the moat as a sensor array, not as a diagnostician. The instruments give breadth across every layer. The missing piece was a place for them to speak one language.

The diagnosis

You had a pile,
not an ensemble.

145 scripts · 8 views · 41 checks — each emits its own format into its own file. Correlation lived in a human head.

"Tools don't work together" and "analysis isn't there yet" are the same problem: no shared substrate. Analysis can't see across tools that don't speak a common language.

→ Fix the substrate first. Everything else becomes a query.

The keystone — the schema

One typed row,
one observation.

{ ts, source, subsystem, signal, severity, value, faulting_module, cpu, confidence, evidence_kind: "observed" | "inferred" | "absent", raw_ref, incident_id, links:[row_id] }

Every instrument appends rows to one append-only timeline. Correlation stops being your brain, becomes a query.

The load-bearing decision

Absence is a third state.

observed

The instrument saw it. A dump bucket. A P-state sample. A dirty shutdown.

inferred

A derived verdict, confidence<1.0, links[] to its evidence. Auditable.

absent

The absence itself is evidence. The 6-min logging silence before the freeze was the single most diagnostic fact.

A two-state schema drops the silence on the floor. This one stores it as a row.

Piece 1 — the flight recorder

The collector,
reframed.

WAS

Writes snapshot.js every 2s so a dashboard can draw a heatmap nobody watches at 10:19.

NOW

Also appends typed evidence rows 24/7. When something dies, the last minutes are already on disk. Additive — dashboard path untouched, wrapped in try/catch so it never breaks the cycle.

Same process, every cycle. It was writing to the wrong target.

Piece 2 — the correlator

The pattern is now
a query.

-- recurrence: which driver keeps doing this? SELECT faulting_module, count(DISTINCT incident_id) FROM evidence WHERE signal LIKE 'dpc_watchdog%' GROUP BY faulting_module; -- nvlddmkm x3 (04-11, 05-11, 05-30) -- misdirection: when is the symptom a lie? felt=network -> truth=cpu_dpc (conf 0.85)

"nvlddmkm × 3" — the cross-month pattern that took human memory, now a GROUP BY.
